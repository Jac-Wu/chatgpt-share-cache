# 拾光 · ChatGPT 分享缓存

把 ChatGPT 的公开分享链接变成一份独立、可搜索、可收藏、可再次分享的文本存档。

支持 `https://chatgpt.com/share/<uuid>` 整段对话分享，以及 `https://chatgpt.com/s/t_<32位十六进制ID>` 单条回复分享。成功解析后返回本站的 `/c/<随机ID>` 访问地址。单条分享只读取对应公开帖子的 `message_slice`，不额外抓取原始完整对话。阅读缓存时不再请求 ChatGPT。项目不使用 OpenAI API，无需 API Key，不读取登录 Cookie，也不执行原网页的 JavaScript。

## 快速开始

需要 **Node.js 22.13 或更高版本**，推荐使用 Node.js 22 LTS。使用 Node 内置 SQLite；某些版本会打印实验性功能提示，不影响正常运行。

```bash
cd chatgpt-share-cache
npm install
npm run dev
```

打开 `http://localhost:3000`。前端和后端共用一个端口，不需要启动两个服务。数据库自动创建在 `data/archives.sqlite`。

### 生产运行

```bash
npm ci
npm run build
npm start
```

构建生成 `dist/` 与 `dist-server/`，`npm start` 使用编译后的服务器和静态前端。请在项目根目录执行命令；使用具有持久化磁盘的 Node 主机，不适合只提供静态页面的托管服务。

## 使用方式

1. 在 ChatGPT 中打开一段对话，创建公开分享并复制链接。
2. 在拾光首页粘贴地址，点击「解析并缓存」。
3. 成功后复制缓存地址，或直接打开阅读页。
4. 在「全部缓存」中搜索标题、摘要或原始链接，使用星标收藏、列表/网格切换、排序、导出 Markdown 和删除。

同一浏览器工作区重复保存同一分享会返回已有地址，**不会自动更新或覆盖快照**。需要重新抓取时，可先导出备份，再删除旧缓存后重新创建；新缓存会生成新地址，旧地址失效。

首页的「灵感陈列室」是明确标注的演示内容，不写入数据库、不计入统计，也不会伪装成已经解析成功的缓存。

### 最近阅读

成功打开一份真实缓存后，会自动将阅读记录保存在当前浏览器的 localStorage 中，访客无需创建自己的缓存。返回首页可在「最近阅读」继续打开最近 6 份对话；侧栏「最近阅读」进入完整记录页，支持标题/摘要搜索、复制地址、单条移除与确认后清空。

- 最多保存 50 条，按最近阅读时间排序；重复阅读更新位置，不产生重复记录。多标签页会同步本机记录变动。
- 仅保存缓存 ID、标题、摘要、消息数和阅读时间，不保存对话正文、管理 Cookie 或所有权信息，不上传阅读记录。它是本机阅读入口，不是离线备份。
- 与「最近缓存」「我的收藏」及其服务器统计分开；阅读他人的缓存不会获得收藏或删除权限，移除阅读记录也不会删除服务器缓存。
- 示例、加载失败和已取消的请求不会新增记录。确认缓存已删除时会移除失效记录；网络错误或临时服务故障不会清除历史。
- 记录仅对同一浏览器、同一站点 origin 有效，域名、IP、协议或端口不同不会共享。清除本站本地存储会丢失记录，隐私浏览记录可能在关闭窗口后消失；此前已读但未记录的页面需要重新打开一次。
- 浏览器禁用本地存储或空间不足时，阅读仍可继续，页面会明确提示记录只在当前标签页内保留；刷新后可能丢失。

### ChatGPT 拒绝服务器访问时

公开分享也可能返回登录要求、浏览器验证、403/429 或超时。本项目不会绕过登录和访问控制，也不会把验证页当成缓存成功。

可以使用「导入网页」：

1. 用浏览器打开原始分享链接，确认完整对话已经加载。
2. 使用浏览器「另存为」保存网页，取得 `.html` 或 `.htm` 文件。
3. 在拾光切换到「导入网页」，填写对应分享链接并上传文件。

只需要 HTML 文件，不需要同时上传资源文件夹。不要上传账户导出文件、登录页或验证页。导入内容由上传者提供，阅读页会明确标注**手动导入、来源未经验证**。如果文件包含分享 canonical 地址且与输入不符，将拒绝导入。

## 能保存什么

- 用户与助手的可提取文本消息，过滤系统提示、工具消息和隐藏推理。
- Markdown 段落、标题、列表、表格、链接、代码块与数学公式。
- 从消息 `metadata.content_references` 还原的可点击引用来源；不会仅凭 `turn...` 内部编号猜测或伪造网址。
- 标题、原始链接、缓存时间、导入方式、提取警告与消息数量。
- 旧版 Next.js 数据、React Router / Remix 引用表、新版 turbo-stream，以及具有消息角色标记的 HTML 正文。

**不是整站镜像：** 不下载图片、音频、视频、附件、Canvas 文件或外部页面，不保证还原交互组件。图片显示为占位提示。原 HTML 仅用于提取，不作为可执行页面公开，也不持久化保存。仅保存解析到的对话分支，不把多个分支混成一段对话。

ChatGPT 分享页不是本项目控制的稳定接口，格式变化可能需要更新解析器。自动抓取还取决于部署机器的网络与上游访问限制；测试夹具不能保证所有真实分享都能成功。

### 引用标记与历史缓存

原始回复中的 `\uE200cite\uE202…\uE201` 是 ChatGPT 使用的内部富文本标记，不是中文 UTF-8 编码损坏。只有标记中的编号、没有配套来源元数据时，普通 Markdown 阅读器无法还原网页引用。

新缓存会将可解析的引用转换为带标题提示的「来源 1」「来源 2」链接；图片和不支持的交互标记会变成明确的文字占位，不执行原网页脚本。阅读页、消息复制和 Markdown 导出使用相同的处理结果。

旧缓存无需删除或修改数据库，刷新阅读页即可将未解析标记显示为「来源未缓存」，不再裸露内部编号。由于旧版本没有保存引用元数据，无法凭空恢复真实出处；需要恢复来源链接时，请先备份，再删除并重新缓存原分享。现有缓存地址、创建时间和管理权限不会因兼容处理而改变。

## 配置

将 `.env.example` 复制为 `.env` 后按需修改。不要把 `.env` 提交到版本控制。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 默认仅在本机监听；需要局域网/容器访问时显式设为 `0.0.0.0` |
| `PORT` | `3000` | HTTP 端口 |
| `ALLOWED_HOSTS` | 空（仅 localhost 和 IP） | 允许访问的域名，逗号分隔，不包含协议或端口；同时用于服务端与 Vite，localhost 和 IP 地址无需添加 |
| `DATA_DIR` | `./data` | SQLite 数据目录，生产环境必须持久化 |
| `FETCH_TIMEOUT_MS` | `25000` | 抓取超时，包含重定向和响应正文 |
| `MAX_ARCHIVES_PER_WORKSPACE` | `500` | 单浏览器工作区缓存数量上限 |
| `MAX_TOTAL_ARCHIVES` | `10000` | 实例总缓存数量上限 |
| `OUTBOUND_PROXY` | 空 | 可选 HTTP(S) 出站代理，如 `http://127.0.0.1:7890` |
| `TRUST_PROXY` | 关闭 | Express 可信代理范围；仅在部署反向代理后配置，例如 `loopback` |
| `ADMIN_SECRET` | 空（禁用管理端） | 管理端登录密钥，32–512 个字符；建议使用 32 字节随机值的十六进制字符串，不使用 `VITE_` 前缀 |

不再需要设置 `PUBLIC_BASE_URL`，旧环境变量会被忽略。缓存链接和来源校验按每次请求的协议、主机及端口动态计算；浏览器展示、复制的缓存地址始终使用当前页面的 origin。同一缓存经域名或局域网 IP 打开时，缓存 ID 不变，返回地址跟随当前入口，不会写回或修改已有数据。使用域名访问时，必须在服务器环境变量或不提交的 `.env` 中配置 `ALLOWED_HOSTS` 并重启服务，无须绑定唯一访问地址。文档和测试中的 `archive.example.com` 仅为示例，不是默认授权域名。

HTTPS 反向代理必须正确转发原始 Host 与协议。直连时 `TRUST_PROXY` 保持为空，忽略客户端伪造的 `X-Forwarded-*`；只有代理实际来源属于配置的可信范围，才会使用这些转发头。同机代理可设 `TRUST_PROXY=loopback`，跨机代理应配置其实际 IP/CIDR，不要信任任意来源。以下示例适用于代理在本站终止 HTTPS，并直接连接应用的情况：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

代理应覆盖而非追加 Host 和协议转发头。HTTPS 请求启用 Secure Cookie 和 HTTPS 安全响应头，HTTP/局域网访问不会被错误升级到 HTTPS。开发模式的 Vite 热更新还需要代理支持 WebSocket；公开部署推荐构建后使用生产服务。

对外部署建议由 Nginx/Caddy 等反向代理提供 HTTPS，配置正确的公共域名、请求体限制（至少与本服务的 12 MB JSON 上限一致）、超时和 IP 限流。不要未经确认就信任所有 `X-Forwarded-For`。公网多用户开放服务还需要额外的用户认证、配额治理、内容合规与运营机制；当前项目是单实例、轻量部署版本。

`OUTBOUND_PROXY` 仅改变部署服务器的出站网络，不会绕过上游的登录、验证或权限要求。工具本身不使用或索要 ChatGPT 登录凭据。

## 全站管理端

访问当前站点的 `/admin`，输入服务器环境变量 `ADMIN_SECRET` 对应的密钥，即可查看所有工作区的缓存。

1. 在服务器执行 `openssl rand -hex 32` 生成随机密钥，并妥善保存。
2. 在项目 `.env` 中新增 `ADMIN_SECRET=生成的密钥`，或通过部署平台的环境变量设置同名值。不要把密钥写入前端代码、URL 或提交到版本控制。
3. 首次部署执行 `npm run build`，设置或修改密钥后重启服务（生产模式运行 `npm start`）。例如通过 `https://archive.example.com/admin` 进入。

- 支持全站缓存数、含缓存工作区数、消息数和内容体积统计；按标题、原始分享链接或缓存 ID 搜索，并按创建时间倒序分页。
- 可阅读、复制当前站点的缓存地址、导出 Markdown；永久删除必须二次确认，会使所有访问者的缓存链接失效，不影响原始 ChatGPT 分享。没有批量删除或回收站。
- 未配置密钥时管理 API 返回 `503 ADMIN_DISABLED`，不会退化成公开列表；过短、全空白或超过 512 字符的配置会拒绝启动。没有默认密钥。
- 登录后使用独立的 HttpOnly、SameSite=Strict Cookie；密钥不写入 localStorage/sessionStorage，Cookie 中保存的是随机会话令牌而非密钥。会话绑定当前访问地址，有效期 8 小时，到期需重新登录。
- 会话摘要只保存在单进程内存中；退出会撤销当前会话，重启服务（包括更换密钥后重启）会使所有会话失效。多进程部署需另行实现共享会话与限流存储。
- 每 IP 每 15 分钟最多 10 次失败登录；公网务必使用 HTTPS，并按上文正确配置 `TRUST_PROXY` 和转发头，确保 Secure Cookie 与来源校验正确。HTTP 直连兼容本机/局域网调试，但不能保护传输中的密钥。
- 普通工作区的列表、收藏和删除仍按原 Cookie 隔离；管理员跨工作区权限仅存在于 `/api/admin/*`。管理列表不返回工作区身份摘要或对话全文。用户浏览器中的「最近阅读」不会上传至管理端。

## 数据与隐私

- 缓存持久化在当前部署的服务器，不是浏览器 localStorage。
- 管理工作区通过随机的 HttpOnly Cookie 识别；数据库只保存令牌的 SHA-256 摘要。
- 普通列表、收藏、删除按工作区隔离；启用管理端后，持有管理密钥的部署者可以查看和删除全站缓存。**持有缓存地址的人均可阅读内容和导出 Markdown。** 这不是需要密码的私密分享。
- 清除 Cookie、换浏览器或使用隐私窗口后，会进入新工作区，无法管理旧缓存。旧数据不会因此自动删除。当前没有账户同步或自助权限恢复机制。
- 删除缓存会使对应地址失效，不会删除原始 ChatGPT 分享。取消原分享也不会自动删除已创建的缓存。
- 请仅保存你有权保存和再次分享的内容，不要存入敏感信息。此工具与 OpenAI 没有隶属关系。
- 备份时先停止服务，再备份整个 `data/` 目录；SQLite 运行时可能存在 WAL 文件，不要只复制正在写入的主数据库文件。复制数据库并不等于迁移浏览器的管理 Cookie。

## 安全边界

- 仅接受 HTTPS 的 `chatgpt.com/share/<uuid>`、旧版 `chat.openai.com/share/<uuid>` 与 `chatgpt.com/s/t_<32位十六进制ID>`，统一规范化。
- 手动验证每一次重定向，拒绝登录页、其他分享 ID、非白名单站点、凭据和非标准端口。
- 最大网页 8 MB，最大会话 1 MB 文本或 1,000 条可见消息，超限明确报错而不是悄悄截断。
- 在独立 Worker 中解析不可信网页，限制内存、解析时长和并发，避免损坏序列化数据影响服务主进程。
- Markdown 跳过原始 HTML，过滤危险链接，禁用不可信数学命令，不自动请求外部图片。
- 生产环境启用 CSP、安全响应头、来源校验和限流；默认每 IP 每 15 分钟最多提交 20 次创建，每分钟最多 240 次 API 请求。
- 这些配额与限流是单实例实现。多进程/多实例需要共享限流存储和更完善的资源管理。

## API

普通缓存管理接口使用当前浏览器工作区 Cookie，`/api/admin/*` 使用独立的管理员会话 Cookie。所有写操作（包括管理登录、退出、删除）要求 `X-Requested-With: Shiguang`；浏览器发送 `Origin` 时必须与本次请求动态解析的访问地址一致，仍会拒绝跨域、跨端口或跨协议请求。API 返回的 `cachePath` 可用于同源跳转，`cacheUrl` 为本次请求对应的绝对访问地址。

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 服务健康状态 |
| `GET` | `/api/archives` | 当前工作区摘要列表与统计 |
| `POST` | `/api/archives` | `{ "url": "公开分享链接" }` 自动解析 |
| `POST` | `/api/archives/import` | `{ "url": "公开分享链接", "html": "网页内容" }` 导入 |
| `GET` | `/api/archives/:id` | 读取缓存，含 `isOwner` |
| `PATCH` | `/api/archives/:id` | `{ "favorite": true }` 收藏或取消 |
| `DELETE` | `/api/archives/:id` | 删除自己的缓存 |
| `GET` | `/api/archives/:id/export` | 下载 Markdown |
| `POST` | `/api/admin/login` | `{ "secret": "管理密钥" }`，成功设置会话 Cookie 并返回 `expiresAt` 毫秒时间戳 |
| `GET` | `/api/admin/session` | 检查管理会话，未登录/过期返回 401 |
| `DELETE` | `/api/admin/session` | 退出并撤销当前管理会话 |
| `GET` | `/api/admin/archives` | 登录后查看全站；`q` 最长 200 字符，`page` 默认 1，`pageSize` 默认 20、最大 100；返回 `archives`、分页、匹配数 `total` 和全站 `stats` |
| `DELETE` | `/api/admin/archives/:id` | 登录后永久删除任意工作区的指定缓存 |

创建成功返回 `201`，已缓存返回 `200`：

```json
{
  "archive": { "id": "随机ID", "title": "对话标题", "messages": [] },
  "cached": false,
  "cachePath": "/c/随机ID",
  "cacheUrl": "http://localhost:3000/c/随机ID"
}
```

失败返回相应 HTTP 状态和 `{ "error": "可读错误", "code": "机器可读错误码" }`。响应字段 `archive` 实际还包含原始链接、时间、统计与提取方式。

## 开发与验证

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

单元/接口测试使用 Node test runner、SQLite 临时数据库和合成分享夹具，不发出真实 ChatGPT 抓取。端到端测试启动独立的生产服务，使用临时数据目录，覆盖导入、复制、去重、收藏、搜索、分享阅读、公式/代码渲染、导出、删除和手机端布局；不会污染日常数据库。

浏览器测试优先使用 macOS 已安装的 Chrome；其他环境先执行 `npx playwright install chromium`，或通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定浏览器。截图与失败轨迹位于 `test-results/`，报告位于 `playwright-report/`。

```text
src/
  components/       输入表单、缓存卡片、Markdown、导航和弹窗
  pages/            工作区首页与独立阅读页
  lib/              API 客户端、工作区状态和工具函数
  demo.ts           明确标注的演示对话
  styles.css        响应式视觉样式
server/
  app.ts            API、安全头、工作区和请求处理
  fetch-share.ts    带超时、限流量和重定向校验的抓取
  parser.ts         多种分享页格式提取
  parse-safely.ts   隔离 Worker 与资源限制

shared/             前后端共享类型
tests/              解析、安全、API、持久化和浏览器测试
```
